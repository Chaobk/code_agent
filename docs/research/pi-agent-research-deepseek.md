# Pi 探索笔记：可借鉴的机制与待验证的问题

2026-10-28 修订。本文最初是模型辅助生成的探索稿，包含未固定版本的生态扩展描述和项目迁移建议。修订后保留有来源支撑的机制与研究问题；源码分析见 [Pi 固定提交研究](pi-coding-agent-design.md)，权限来源复核见 [Pi 权限核查](pi-permissions-primary-check-20261022.md)。当前契约与实施顺序见 [PLAN.md](../../PLAN.md)。

## 循环、会话与界面的职责

固定提交研究区分供应商适配、Agent 调度，以及会话持久化与 UI。值得学习的是职责如何通过消息和接口连接。原稿未给出版本依据的 pi-telemetry、pi-protocol / pi-client / pi-server 包清单不再作为已核实架构。

Pi 的所研究快照支持并行工具执行。本项目继续顺序执行；调用顺序、完成顺序和消息写回顺序需要分别定义。并行收益还取决于独立性、写冲突、取消和部分结果处理，不能由“多个只读工具”直接推断改动小、成本低。[循环与工具调度分析](pi-coding-agent-design.md#工具从模型参数到真实副作用)

Steering 和 follow-up 展示了运行中输入的不同调度位置。本项目多轮 REPL 已实现，但尚无这套队列。引入前需回答：新输入何时成为历史，能否打断正在执行的副作用，取消时未消费消息如何处理。

## 原始记录与模型输入

Pi 的会话树、压缩条目和投影展示了保存原始记录与缩小请求的职责边界。保留条目不代表所有运行信息都完整或耐久落盘，摘要也可能丢信息。[投影与压缩分析](pi-coding-agent-design.md#上下文完整记录有效分支与本次请求分别管理)

本项目 M5a 先做已提交消息的增量 JSONL 与只读回放；恢复、记忆、检索和上下文预算分别实施。不能将 History 中的原消息替换成摘要，再把它当作完整轨迹。工具层已有字符保留预算；未来若另存完整输出，还需定义来源引用、文件寿命与访问方式。

上游 reserveTokens 等数值属于特定提交与模型配置。研究时关注触发条件、合法切点和失败恢复；实际请求预算还要计入系统指令、工具定义、当前输入、历史、检索与回复预留。

## 权限分析的范围

Pi 的已核查接点位于参数校验后、工具执行前，扩展可阻止调用。扩展本身仍是可信进程代码，接点不限制它任意发起的 I/O。[固定提交安全说明](https://github.com/earendil-works/pi/blob/be14d9732f98fcc33929cf103a92b96afaa6523e/packages/coding-agent/docs/security.md)

Gatekeeper 可用语法树识别部分重定向、动态构造和复合命令，但 AST 表达语法，不能证明任意脚本的运行时副作用。解析器初始化失败还存在正则回退路径，不能概括为所有故障都拒绝。[分析器源码](https://github.com/noel-debug/pi-gatekeeper/blob/main/analyzer.ts)

原稿的示意代码只按命令名放行 find、git 等，未检查参数副作用，重定向和路径判断也不完整，因此移除。后续实验至少应覆盖 find -exec、git reset --hard、解释器载荷、引号、命令替换、换行和解析失败。复合命令须按 shell 语法理解，直接按 &&、分号或竖线切字符串会误判字面量并遗漏其他构造。

AST、规则、模型审查、人工确认与 OS 隔离分别解决不同问题。原稿“覆盖所有结构漏洞”“150–200 行完成”等断言缺少验证，不能作为实现承诺。独立模型裁判只是候选路线；当前基础审批已接线，命令规则和会话授权范围仍待完善，以计划为准。

## 轨迹写入的顺序与失败语义

UI 事件没有覆盖所有历史提交，包括取消收尾的补写观察。因此完整消息轨迹应连接 History 成功提交的边界，不能仅订阅屏幕事件。[M5a 规格](../design/m5a-tracing.md)

包含工具调用的助手消息写入成功后才执行工具。写入失败应报告并停止后续动作，同时结清已有 pending；它会影响控制流，不能称为完全无关的旁路观察者。flush 改善应用进程强杀时的留存，不承诺断电安全，也不能让外部副作用与日志原子提交。缺少结果时保持状态未知，不自动重跑；回放有效前缀与恢复执行分别验收。

## 子任务与评测

Pi 官方子任务扩展使用子进程和 JSONL 交接；独立会话不等于文件写入隔离，也不自动具备 A2A 或完整协作框架。[子任务分析](pi-coding-agent-design.md#多-agent官方示例做了什么没有做什么)

本项目 M8a 从独立历史的只读子任务开始，由主 Agent 核实证据，处理失败、取消及矛盾结果。后台任务、可恢复调度和邮箱不能从“能启动子进程”直接推出。

所研究固定提交已有 packages/evals，原稿“评测全部由外部 Harness 承担”的说法过宽。可借鉴固定初始状态、独立判分、重复运行和完整失败分母；框架存在不证明任务成功率提高。AST、JSONL 与性能收益未经实测的部分，也不能写进已经完成的面试经历。[评测分析](pi-coding-agent-design.md#测试与-agent-评测分别回答实现对不对和任务做得怎样)
