# 架构与模块职责

本文说明当前运行路径、模块边界和预留模块的设计安排。实施顺序、进度和验收标准以 [PLAN.md](../../PLAN.md) 为准，历史调整见 [计划历史](../plan-history.md)。

## 当前运行路径

CLI 的 `-p` 与终端会话入口从配置创建 Agent，通过事件回调显示进度，通过 RunResult 显示结束原因。具体源码阅读顺序见 [运行流程](run-flow.md)。Agent 持有客户端、工具注册表和消息历史，每次 `run` 追加用户输入，再执行模型与工具循环。

1. 使用配对完整的历史和工具定义请求模型。
2. `TurnAssembler` 累积正文与工具参数分片；正文增量可以立即显示。
3. 流正常耗尽并通过完整性校验后，将完整助手消息写入历史。
4. 按顺序校验工具参数并检查权限，必要时确认；获准才执行 handler，拒绝则生成未执行观察。将每条结果写回历史，再发送结果事件。
5. 有工具调用时继续请求模型；无调用正常结束返回 RunResult(completed)，已知模型失败返回 failed，达到上限返回 max_steps。原生取消和内部故障在统一历史收尾后向外传播。

流异常或取消时，尚未提交的助手消息不进入下一次模型输入，也不执行其中的工具调用。当前循环在 `core/agent.py` 中，已接入基础权限审批；独立模式对象尚未接入，持久化轨迹处于 M5a 练习中，尚未接入默认 CLI。

## 模块职责

| 模块 | 当前职责 |
|---|---|
| `core/agent.py` | 创建依赖、绑定执行环境，协调模型请求、历史提交、工具执行和运行事件 |
| `llm/client.py` | 用 OpenAI SDK 请求兼容服务，复用连接池，返回完整响应或原始分片 |
| `llm/streaming.py` | 组装文本与工具调用分片，检查结束原因及完整调用结构 |
| `context/history.py` | 保存消息快照，校验调用 ID 配对，阻止未配对历史进入模型请求 |
| `tools/spec.py`、`tools/registry.py` | 生成工具 schema、注册工具、校验参数并分发调用 |
| `tools/builtin/` | Bash 执行、输出收集与进程清理；另有可单独使用的文件读取工具 |
| `safety/policy.py` | 校验执行目录和 Bash 路径，返回规范化的执行环境 |
| `safety/permission.py`、`approval/` | 权限决定类型、策略协议、审批协调与终端确认；Bash 的简单规则位于工具实现中 |
| `events.py` | 定义共享消息、工具结果、RunResult 与三类进度事件 |
| `ui/` | 解析命令行参数，显示事件和消息历史 |
| `config.py` | 加载运行配置 |

默认工具注册表只注册 Bash。`read_file` 的实现和测试保留，其他专用工具按实际需要增加。

跨模块对象创建与业务编排集中在 core。UI 调用核心入口；模型、工具和历史模块通过传入对象与共享数据类型协作，不自行创建其他能力的业务依赖。终端渲染留在 UI，核心通过回调发送事件。

模型客户端在首次请求时创建，默认连接 DeepSeek；`base_url` 决定服务地址，`model` 使用服务端名称。迁移前的 `deepseek/` 前缀在请求边界移除，密钥仍从 `DEEPSEEK_API_KEY` 读取。SDK 显式设置 `max_retries=0`，每次请求仍可覆盖连接参数、模型与 HTTP 超时。流结束、错误、提前关闭或取消都会释放响应；CLI 在单次任务或整个交互会话退出时调用 `Agent.close()`，由核心关闭模型客户端。交互会话的单次运行取消不关闭连接池，下一次输入可继续请求。

## 执行与状态边界

### 执行环境

应用配置决定工作目录和 Bash 路径，模型只传入命令和超时时间。`create_agent` 在创建客户端前校验路径；内置工具通过绑定参数使用该执行环境。

每次 Bash 调用启动独立进程，`cd`、`export` 不跨调用保留。stdout 和 stderr 并发读取，共用字符保留预算；达到预算后仍继续排空管道，避免阻塞子进程。超时和取消会尝试清理已发现的进程树，快照查询可能遗漏后代。进程清理的详细取舍见 [进程清理研究](../research/process-cleanup.md)。

固定 cwd 只决定命令从哪里开始执行，不限制绝对路径、上级目录或网络访问。当前路径校验不提供文件隔离，后续命令规则和 OS 隔离须分别说明实际保护范围。

### 工具结果与取消

`COMPLETED` 表示取得了工具结果，Bash 非零退出也使用该状态，原始退出码保存在 output 中。参数校验和工具自行处理的预期操作失败返回 `ERROR`，妥善清理的超时返回 `TIMED_OUT`；取消、内部和清理异常继续传播。Registry 不捕获所有 handler 异常。详细结果约定见 [工具结果研究](../research/tool-results.md)。

工具执行中取消时，核心保留已有观察，补齐未完成调用的配对结果。当前调用无可确认结果时标记为 `unknown`，未启动的调用标记为 `not_started`，随后传播取消。恢复或后续运行不能据此自动重跑副作用未知的命令。

历史写入采用先校验、后更新的方式。输入消息和读取结果使用深拷贝，避免调用方修改已保存的历史。终端显示可以替换最后回复的呈现文本，但不修改历史。

## 预留模块与后续设计

下表说明尚在实施或预留的能力，具体接口以各阶段的有效规格为准。

| 文件或模块 | 阶段 | 设计安排 |
|---|---|---|
| `approval/`、`safety/` | M4c | 基础策略与确认已接线；命令分析、授权范围细化等仍待完善，完整 M4c 未验收 |
| `memory/working.py` | M5 | 基于已有历史按需要提取任务状态，避免提前维护重复的状态系统 |
| `memory/longterm.py` | M5 | 文件存储少量事实和经验，保留来源及有效状态，先使用关键词检索；与消息恢复、轨迹分别管理 |
| `tracing/jsonl.py`、`core/trace.py` | M5a | 按练习规格实现会话 JSONL 与只读回放；当前未完成，默认 CLI 尚未接入 |
| `context/` | M6 | 保留完整记录，为本次请求派生受预算约束的输入；历史、记忆与检索片段共同考虑 |
| `modes/base.py`、`react.py`、`plan.py` | M6 | 先实现第二种 plan-execute 模式，再从实际差异提炼接口，复用工具和历史 |
| `tracing/` | M7 | 为评测补充实际可得的调用、用量和耗时记录；精确成本报表按需要增加 |

长期记忆、原始历史、轨迹和恢复检查点具有不同用途。源码按任务需要通过工具读取；系统指令、会话历史以及未来选取的记忆和检索片段分别管理。不会自动把整个项目或全部长期记忆注入请求。

命令分析与审批的候选方案见 [命令权限研究](../research/command-permission-policies.md)。OS 沙箱、向量数据库和独立模型审批仍按计划作为可选扩展。

## 源码说明的范围

模块文档字符串说明当前职责；类和函数说明输入、返回值、副作用及调用限制。行内注释用于解释不直观的原因，例如历史的原子更新、PID 复用和异步清理约束。

学习目标、阶段编号、实现步骤、协作分工和验收记录集中放在计划、设计文档与历史记录中。未实现的文件只标明用途和未实现状态，避免把设计设想写成已有行为。
